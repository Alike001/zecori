## Start without a wallet

You can inspect the route, terms, custody model, limitations, and assistant explanations while signed out. Zecori asks for an account only when you request an owner-scoped review.

## Passkeys protect the Zecori account

Passkeys are the verified account path. Add a second passkey while authenticated so one lost device does not strand the account. A Zecori account protects private order history; it does not control a wallet.

## Zcash source wallet

The source selector is wallet-neutral and has two honest paths:

- **Connect Noir Wallet** is an integrated guarded readiness check. It detects, connects, reads only authorized account readiness, and invalidates on account, chain, or stale-balance changes. Sending stays disabled because the current provider cannot prove the exact testnet build or Ironwood spendability to Zecori.
- **Use another Zcash wallet** is an external-instructions path. No named wallet is claimed compatible. Only an owner-scoped, unexpired `PAYMENT_READY` request can reveal the full allocated shielded receiver, exact amount and chain, immutable order terms, copy control, and receiver-only QR. There is no transparent-funding fallback.

The public demo never publishes a receiver. An external-wallet selection is not a compatibility or payment-success claim.

## Base receiving wallet

A connected Base wallet is the preferred recipient path and is inspected with `eth_chainId` and `eth_accounts` only. Manual recipients are intent only: they are validated locally for exact EIP-55 checksum, zero address, and hidden clipboard changes, but do not prove ownership. Both paths bind Base Sepolia chain 84532, the exact test-USDC contract and recipient. A later, purpose-limited EIP-712 signature proves control of that exact recipient; account or chain switching invalidates the attempt, and Zecori never substitutes another address. The signature does not authorize payment, payout, token transfer, or transaction signing.

## Privy

Email and Google sign-in are integrated behind a disabled feature flag. Tokens are verified server-side and linked to internal UUID accounts only after explicit authenticated consent. No embedded wallet is created.
